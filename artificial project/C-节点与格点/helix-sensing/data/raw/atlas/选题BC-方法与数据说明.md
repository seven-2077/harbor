# 选题 B / C：方法与数据说明

本文不是已定题目，只说明这两条**候选方向**今晚能依据什么、还缺什么。云电脑上**没有实物板，没有实机采样**。芯片型号已由主人确认为正点原子 STM32F407ZGT6；凡涉及“这块板接了什么传感器”“是哪一套件”的内容，仍是未知或推断，下面逐条标明。

选题 B 的常见提法：在一块 STM32 开发板上做多传感器采集、本地存储，再做交互可视化（校园/室内环境或行为套件）。选题 C 的常见提法：把本地 STM32 序列与一份公开环境或时空数据对照（例如室内舒适度对室外气象/空气质量）。具体标题留给 Folio，本文只给方法与数据口径。

## 2. 按数据手册，这块芯片*能够*采集什么

以下是 **芯片外设能力**（来自 DS8626 Rev 12 对 STM32F407Zx / 144 引脚产品线的公开描述），不是“这块板已经焊了哪些传感器”。

| 外设 | 数据手册口径（量级） | 对环境/行为采集的含义 |
| --- | --- | --- |
| ADC | 3 个 12 位 ADC；144 引脚产品线最多 **24 个外部通道**；单 ADC 转换速率可达 **2.4 MSPS**，交错模式可达 **7.2 MSPS** | 可采模拟量（分压后的气体传感器、光敏、简易麦克风等）。环境类应用通常只要 **0.2–1 Hz** 甚至更慢，不必用到 MSPS。若 VDDA/VREF+ 按常见 3.3 V 估计，1 LSB 约 0.8 mV——这是电侧分辨率，**不是**气体或温湿度的标定精度 |
| 内部温度传感器与 VREFINT | 经 ADC 内部通道采集 | 数据手册明确：内部温度传感器**更适于检测相对变化**；若需要准确温度，应使用外部传感器。不要把它当成室内气温 |
| I2C | 3 路，标准模式 100 kHz / 快速模式 400 kHz | 常见数字温湿度、气压、光照、部分 IMU、气体模块走这里 |
| SPI | 3 路 | 可接 SPI 闪存、部分 IMU、部分高精度 ADC 或显示 |
| USART / UART | 4 路 USART + 2 路 UART | 可向电脑或 Helix 输出采样流。常见教学配置是 115200 8N1，**这是实践习惯，不是已核实的板级设置** |
| GPIO | 最多 114 | 按键、LED、GPIO 触发采样、片选 |
| 存储器与主频（便于判断能否本地缓存） | 168 MHz Cortex-M4；Flash 1024 KB；SRAM 192 KB + 4 KB backup SRAM | 适合做本地环形缓冲和按行输出；大批量历史仍建议落到 SD 卡或立刻传到主机。板上是否有 SD 卡槽**未见实物，不得写成已有** |

精度与采样率怎么写进方法部分（建议口径）：

- **电侧**：12 位 ADC，分辨率量级为毫伏（取决于参考电压）；线性误差以数据手册 ADC 电气特性表为准，不要用 MSPS 去暗示环境量已经达到同等“精度”。
- **传感器侧**：以所接传感器自己的数据手册为准。在未见 BOM 之前，只能说“常见 I2C 温湿度传感器的标称误差量级大约是温度零点几到约 1 °C、相对湿度几个百分点”——这是**品类量级，不是这块板的指标**。
- **时间同步**：芯片没有联网 RTC 授时就不能假设有可靠绝对时墙钟。选题 C 若要和公开小时数据对照，必须在主机侧给记录打上主机时间，或为板子提供 RTC 并对时。模拟样品里的时间戳是后补的示意，不是板子自己的钟。

## 3. 这块板*实际接了哪些传感器*：全部为推断

云电脑未见原理图、未见照片、未见固件。下面是按**常见 STM32F407 教学/探索板配置**写下的*可能*采集对象，供 Helix 设计数据通路和模拟流。**每一条都是推断，落实前必须对照实物。**

| 推断的传感器或通道 | 推断的接口 | 可提供的量 | 状态 |
| --- | --- | --- | --- |
| BME280 或同类温湿度气压（SHT 系列也可） | I2C（示例写 I2C1） | 温度、相对湿度、气压 | **推断**（常见模块，非已核实 BOM） |
| BH1750 或同类环境光 | I2C | 照度（lux） | **推断** |
| MQ-135 或同类模拟气体传感器 | ADC | 仅原始 ADC 码；未经标定不能当 ppm 或官方空气质量指数 | **推断**；绝对浓度尤其不可靠 |
| 片内温度传感器 MCU_TS | ADC 内部通道 | 芯片相对温升 | **芯片上有此外设**（数据手册）；用来代表室内气温则不合适 |
| 可选 IMU（如 MPU6050 一类） | I2C 或 SPI | 加速度/角速度，行为或姿态套件才需要 | **推断，且非环境对照所必需** |

引脚分配（例如 USART2 的 PA2/PA3、I2C1 的 PB6/PB7）在不同厂家的 F407ZG 板上并不统一，**本文不提供“已核实引脚表”**。Helix 做固件骨架时可先用上述逻辑总线名（I2C1、ADC1、USARTx），等见到原理图再绑定引脚。

## 4. 推荐的本地存储与 Helix 接入格式

建议主格式为 **JSONL**（一行一条通道记录，便于追加和流式读取），并用字段完全相同的 **CSV** 作为表格与可视化入口。串口旁路可输出一行一个采样周期的文本，但入库仍拆成与 JSONL 相同的字段。

所有流式文件以 `#` 开头的行视为注释（Helix 应跳过）。实机文件同样建议在文件头写明 `device_id`、固件版本、时区。**模拟文件第一行必须是「# 模拟，非实机」。**

### 字段设计

| 字段 | 说明 |
| --- | --- |
| `timestamp_utc` | UTC，ISO 8601，以 `Z` 结尾，例如 `2026-08-03T04:00:00Z` |
| `timestamp_local` | 本地时间，带偏移，例如 `2026-08-03T12:00:00+08:00`（Asia/Shanghai） |
| `device_id` | 设备标识。模拟用占位符 `stm32-f4zg-sim-01`；实机应写烧录号或板级序列，不要与模拟 ID 混用 |
| `firmware_rev` | 固件或生成脚本版本 |
| `seq` | 采样周期序号（同一时刻多通道共享同一个 `seq`） |
| `sensor_id` | 传感器名，如 `BME280`、`BH1750`、`MQ135`、`MCU_TS` |
| `bus` | 逻辑总线，如 `I2C1`、`ADC1`、`USART2` |
| `channel` | 通道，如 `temperature`、`relative_humidity`、`pressure`、`illuminance`、`gas_adc`、`gas_index`、`mcu_temperature` |
| `raw_value` | 原始整数（ADC 码或传感器原始寄存器换算前的整数） |
| `value` | 按该通道单位换算后的值 |
| `unit` | `degC`、`percent`、`hPa`、`lux`、`lsb`、`index` 等 |
| `quality_flag` | 如 `ok`、`simulated`、`uncalibrated_simulated`、`relative_only` |
| `source` | `device` 或 `simulated` |
| `notes` | 短备注（标定状态、推断来源等） |

不要只存换算值而丢掉 `raw_value`：气体和片内温度尤其需要保留原始码，便于以后重标定。

时间窗与选题 A 的一周窗口、以及下方 Open-Meteo 兰州样品的同一天对齐，仅方便以后做“对照方法”的演示，**不代表兰大校园实测**。

| 文件 | 说明 |

| `samples/stm32_sim_usart_lines_example.txt` | 同一时间窗的示意串口行（一行一个周期） |

Helix 接入建议：先读 CSV/JSONL（跳过 `#` 行）做同一解析器；再把解析器接到模拟串口（可把 USART 示例按行写入虚拟终端）。数值是发明的，只 loosely 参考了同日 12:00 兰州室外公开气象的量级（约 26 °C、约 50% 相对湿度、约 852 hPa），加上室内偏差与噪声。

## 5. 选题 C 的公开对照数据（可下载、许可证清楚）

主推 **一组**来自 Open-Meteo 的互补数据（不是两个无关平台）：

1. **空气质量小时序列**（Air Quality API，源数据文档写明来自 CAMS）
2. **历史气象小时序列**（Historical Weather / Archive API，文档写明基于 ERA5 / ERA5-Land / 2017 年起的更高分辨率模式等）

二者都已在今晚用公开、免密钥接口实际下载成功（HTTP 200）。坐标用兰州市区一个**城市参考点**（约 36.06°N, 103.83°E），**不是测量过的校园或办公室坐标**（推断/近似）。接口还把点吸附到各自的模式格点，空气质量与气象返回的经纬度并不相同（见下表）。不要把格点值写成“兰大某栋楼的监测站读数”。

### 5.2 选题 C 建议的对照方法（不做最终可视化）

1. 本地 STM32 流按 `timestamp_local` 归到整点（例如 12:00–12:59 取中位数或均值）。
2. 与 Open-Meteo 同一整点的 `temperature_2m`、`relative_humidity_2m`、`surface_pressure` 或 `pm2_5` 等列并排。
3. 必须在图例和文字中同时写清：一边是**点式室内（或校园）传感器**（实机尚未采集；今晚只有模拟），一边是**模式格点上的室外大气产品**，空间尺度差一到两个数量级；气体通道若未标定，不得与 CAMS 的 μg/m³ 做数值等同比较。
4. 坐标改为实测教学楼经纬度之前，继续使用“兰州市区参考点”这一表述。若以后要对照纽约客流，应另下纽约点的 Open-Meteo，而不是用这份兰州样品。
