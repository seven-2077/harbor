# 选题 A 数据清单

本清单只覆盖**候选方向 A**（公开城市轨道交通时空数据）。B/C 见 `选题BC-方法与数据说明.md`。本文只写今晚已核对的事实；推断单独标明。采集时区：Asia/Shanghai（UTC+8），日期 2026-11-11。原始探测过程见 `来源与许可证/采集记录.md`。

## 为何只推这一组、不并列第二座城市

题目需要「空间 + 时间」且能做交互可视化。纽约地铁这组满足：官方静态线网（GTFS）可直接下载；官方小时客流有明确字段和门户条款；两者可用官方车站表（`complex_id` ↔ `gtfs_stop_id`）连接。第二座城市若只找到 GTFS 而没有同等粒度、同等条款清晰的小时客流，或需要登录/爬虫，就不作为主推并列。其他城市（例如只有站点层、没有小时进站）可作后续扩展，今晚不展开。

### 空间与时间字段（使用时主要看这些）

- 空间：`stops.txt` 的 `stop_lat` / `stop_lon`，`location_type`，`parent_station`；`shapes.txt` 的折线点。
- 时间：`stop_times.txt` 的 `arrival_time` / `departure_time`（可超过 24:00）；`trips.txt` 的 `service_id`；`calendar.txt` / `calendar_dates.txt`。
- 线网：`routes.txt`、`trips.txt` 的 `route_id` / `shape_id`。

### 单机是否合适

适合。压缩包约 5.6 MB。`stop_times` 56 万行、`shapes` 15 万行，用 pandas / GeoPandas / DuckDB 在普通笔记本上可一次载入。无需集群，也不需要 GPU。

### 重要限制

当前 feed 的服务日期从 **2026-11-01** 起，与下方 2026-08 客流**没有日期重叠**。可以用地图底图（站点和 shapes），不要把这份 `stop_times` 当作 8 月实际班次。若需要与 8 月客流对齐的历史 GTFS，应另找该窗口的存档；Transitland 上可见到服务期覆盖 2026-05-26–2026-10-31 的条目，但其 REST API 无密钥返回 401，今晚**未下载**该历史包，不把它当作已核验样品。

### 为何样品不是官方全量 CSV

本执行环境对 `data.ny.gov` / `www.mta.info` 的 curl 返回 **403**。官方接口通过 WebFetch（另一出口）可读。因此：

- 保存了官方 SODA `$limit=8`（未加 `$order`）的**原样** 8 行：`samples/subway_hourly_ridership_official_api_limit8.csv`（1,508 字节，SHA256 `fbcb560a170cc04d2501618eb48bdb904cd30ac60e23bc44d7ce05a660330304`）。行日期为 2025-05-23，说明默认切片不是 2026-08。
- 实操可用的完整月文件来自第三方按月镜像 **transitlab.nyc**（页面说明镜像自官方表）：`https://data.transitlab.nyc/v1/subway_hourly_ridership/year=2026/month=08/2026-08.parquet`  
  - 样品：`samples/subway_hourly_ridership_2026-08.parquet`  
  - 4,668,476 字节；SHA256 `2abb15137229e1993c4ca7d2952153334b42adb09bca109e1a858e1f1f0d92a6`  
  - Last-Modified：Sun, 25 Oct 2026 07:01:37 GMT（合 Asia/Shanghai 2026-10-25 15:01:37）  
  - 实测：1,706,182 行；时间 2026-08-01 00:00 至 2026-08-31 23:00，31 天齐全；无空值；无单独的几何列（经纬度已作为列给出）。  
  - `transit_mode`：subway 1,693,527 行 / SIR 6,732 / tram 5,923。  
  - 428 个不重复 `station_complex_id`。subway 模式 ridership 合计 105,456,157。

**推断（必须标清）**：transitlab 月文件与同时点官方全表在数值上完全一致——今晚未对官方全月做逐行对账（官方全月导出受 403 与体量限制），不能写成“已逐行核验等同”。8 行官方切片已证明字段名和门户可读。

### 官方字段（以数据字典 / 元数据为准，样品中见到的列与此一致）

常见列：`transit_timestamp`，`transit_mode`，`station_complex_id`，`station_complex`，`borough`，`latitude`，`longitude`，`payment_method`，`fare_class_category`，`ridership`，`transfers`，以及地理辅助列（如 `georeference`，视导出格式而定）。

口径注意（来自官方说明，摘录见 `来源与许可证/客流数据字典与第三方说明摘录.md`）：

- 一行 = 某一小时、某一车站复合体、某一支付方式、某一票种的进站估计。分析“该站该小时总进站”必须按小时+车站把各票种相加。
- `transfers` 已计入 `ridership`，不可再加总。元数据允许 `transfers` 为负（最小见到 -30.0）。
- 字典用词与表中实际取值可能有细微差别（例如字典 “OMNY – Seniors & Disabilities”，样品值为 “OMNY - Seniors & Disability”）。

### 与 GTFS 的连接（官方车站表，未放入 samples 的原因）

官方映射表：data.ny.gov `39hk-dx4f`（MTA Subway Stations）。今晚 WebFetch 读到 **496 行**，与 GTFS `location_type=1` 父站数相同。字段包括 `gtfs_stop_id`、`station_id`、`complex_id`。`rowsUpdatedAt` 合 Asia/Shanghai **2026-11-10 13:18:45**。

抽查（事实）：ridership 的 Prince St（complex 17）↔ 车站表 complex 17 ↔ `gtfs_stop_id=R22`；Hewes St 100 ↔ M14。Times Sq 复合体 611 对应多个父站（见到 R16、A27、127、725、902）。即：**一个客流复合体可以对应多个 GTFS 父站**，地图上不要假设 1:1。

未把 496 行全表写入 `samples/`，避免从 WebFetch 转抄后冒充官方原文件。请自行下载：

`https://data.ny.gov/resource/39hk-dx4f.csv?$limit=500&$order=station_id`

若该域 403，换网络或浏览器。连接步骤见 `方法路径.md`。

### 单机是否合适

| 范围 | 结论 |
| --- | --- |
| 一周加总 CSV（约 5.5 MB） | 适合直接用 pandas / 电子表格做原型 |
| 整月 parquet（约 4.7 MB；pandas 载入约 200–250 MB 内存） | 适合 8–16 GB 内存的笔记本；建议用 DuckDB / Polars 做过滤后再进可视化 |
| 官方 Beginning 2025 全表 4,740 万行 | **不适合**用 pandas 一次性读入。应用 DuckDB 直接查 CSV/parquet，或按月切片。笔记本 8 GB 显存与此无关 |

## 许可与再分发（选题 A 汇总）

1. **GTFS**：按 MTA data feed 条款使用、本地托管和做应用；可用子集；不要改原始取值、不要把 MTA 服务器当自己的后端、不要擅自用标志/官方地图、不要作准确性声明。条款本身允许将 feed 放到非 MTA 服务器后再分发或开发。
2. **小时客流**：没有数据集条目上的标准 SPDX 许可证。遵循 OPEN-NY Terms of Use（非独占、可撤销许可等，详见摘录）。成品须注明来源为 MTA / data.ny.gov；若实际文件来自 transitlab，同时注明 transitlab.nyc。不要把门户条款改写成 CC-BY。
3. 本目录 `samples/` 中的派生 CSV 是为课程/毕设原型准备的切片，同样受上游条款约束。

## 备选方向（仅短注，不是今晚主数据）

- **城市空气质量时空数据**：见选题 C 所采用的 Open-Meteo（CC BY 4.0，今晚已下载兰州一周样品）。可单独做环境可视化，但与“轨道交通”主线不同。
